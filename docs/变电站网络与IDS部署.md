# 变电站网络与 IDS 部署

本分支采用站控网与过程网分设交换机的部署方式。站控层、间隔层、过程层仍表示设备功能归属；网络连接按场景中的接口清单绘制。

## 网络接入

| 网络 | 交换机端口 | 接入设备 | 设备接口 |
| --- | --- | --- | --- |
| 站控网 | P1 | 站端监控系统 | ETH-ST |
| 站控网 | P2、P3 | 过流保护装置、测控装置 | 各自的 ETH-ST |
| 过程网 | P1、P2 | 过流保护装置、测控装置 | 各自的 ETH-PR |
| 过程网 | P3–P5 | 断路器、分接机构、冷却系统的控制接口 | 各自的 ETH-PR |
| 过程网 | P6 | 合并单元 | ETH-PR |

保护和测控装置分别接入两张网，两个接口没有交换或桥接关系。两台交换机之间没有业务连接。图中相交的线不表示连接，端口圆点才是接线端点。

传感器到合并单元显示为本地采集接线，控制接口到一次设备显示为硬接线。专用授时线独立绘制。电气主回路、热耦合、电磁干扰和原场景的外部无线关系按各自含义保留。原有外部关系不据此扩展成完整的调度数据网。

## IDS 与安全监测平台

两台交换机分别配置 SPAN1，复制全部已列接入端口的收发流量。每个 IDS 通过 CAP0 接收镜像，通过独立的 MGMT 接口向安全监测平台上报。镜像支路与上报通道不参与业务报文路由。

| IDS | 事件采集口标识 `metadata.interface_id` | 无采集口字段时匹配 `source_id` |
| --- | --- | --- |
| 站控网 IDS | span-station | ids-station |
| 过程网 IDS | span-process | ids-process |

事件沿用《五类监测接口数据交付规范》的 `source_type=ids` 契约。配置 `provider_id` 时还会核对提供方。已提供但不匹配的采集口标识不能通过 `source_id` 兜底，以免把未知来源的告警归到错误网络。

界面按当前观测窗口显示事件数、告警数、原始等级、协议、关联设备与数据来源。`alert` 事件或 `status=anomaly` 显示告警；收到其他 IDS 事件显示“已收到事件”；没有事件显示“暂无采集数据”。这三个状态不用于推断采集硬件在线或网络安全。合成事件明确标注“合成数据”。电磁攻击作用与仿真真值不会自动生成 IDS 告警。

## 配置与实现范围

部署清单位于三个变电站场景的 `layout.deployment`，随运行 manifest 保存。`networks[].connections` 声明物理接口与交换机端口，`business_ports` 将现有仿真业务端口映射到物理接口，`link_ids` 声明该网络承载的业务关系。前端据此绘制独立接入线，并计算报文经过对应交换机的路径。

加载场景时校验设备和端口引用、业务关系归属、接口隔离、镜像端口及 IDS 采集／管理口分离。旧场景没有部署清单时继续显示原有拓扑。

本次实现是前端部署拓扑和观测展示。后台仍使用现有 `Message` 与逻辑连接计算业务投递，交换机图形没有额外引入转发时延、MAC 学习或交换机故障模型；报文详情展示内部 Message，不声称生成了 IEC 61850 线路帧。IDS 状态来自外部观测契约，当前三个场景未配置 IDS 采集数据源。

此配置没有现场工程图作为依据，也没有声明 PRP／HSR、双套保护、VLAN、调度出口防护或安全分区。站控网和过程网的两台交换机不能解读为冗余 A/B 网。现场部署还需按实际设备接口、SCD、交换机配置和采集能力核对；不能把本场景称为某座实际变电站的竣工图。

## 依据

- [SEL：Substation Automation Solutions](https://selinc.com/solutions/substation-automation/)：站控总线与过程总线的功能，以及数字二次系统的不同实现。
- [NIST SP 800-82r3，第 6.3.2.1 节](https://nvlpubs.nist.gov/nistpubs/SpecialPublications/NIST.SP.800-82r3.pdf)：在适当网络位置使用 SPAN／TAP 采集流量并开展网络监测。
- [南瑞继保：网络报文记录及分析装置投运案例](https://www.nrec.com/cn/index.php/news/info/865/24)：分别采集过程层和站控层报文的工程案例。报文分析装置的功能与安全 IDS 的检测能力应分别核实。
