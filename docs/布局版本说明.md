### 复数采集链路的行为

第二套合并单元按首套的行为接入：`mu_2.out` 经过程网同时送到过流保护装置与测控装置（`L-mu_2-mc`、`L-mu_2-prot`），测控装置与站端把它作为独立来源如实展示。

- 量测通道：`ct_current_2` 声明 `channel: "ct_current"`，与首套互感器共用同一量测通道名，下游无需为第二套新增通道。
- 测控装置：采样按来源分别保留（不再单值覆盖），上报量测改为按来源分组的 `sources`；站端面板与测控面板逐条显示“来自 合并单元 / 合并单元-2”的数值，两套偏差超展示容差（`MEASUREMENT_COMPARE_TOLERANCE = 0.01`）时高亮提示“量测不一致”。该提示只是数值比对，不构成攻击判定。
- 过流保护：采样同样按来源分别保留，每个来源各自累计持续时间；任一来源持续越限达到整定次数即出口，并在跳闸命令与保护事件里标注触发来源（`parameters.source`）。

### 差动保护装置

间隔层新增 `diff_prot`（差动保护装置，`device_type: differential_protection`），位于间隔层 `x=465`：

- 经过程网接收两套合并单元的量测（`L-mu-diff_prot`、`L-mu_2-diff_prot`），比较同一通道的**绝对差**，超过整定值即向断路器智能终端下发 `trip`（`L-diff_prot-brk`），并经站控网上报保护事件（`L-diff_prot-station`）。
- 整定值 `differential_threshold_a`（默认 10 A）通过 `describe_controls()` 暴露，点选该设备即可在演示平面修改，无需改前端；`compare_mode` 预留比较方式（当前仅 `absolute`）。
- 动作后保持，差流复归后才允许再次动作，避免每个判断周期重复下发相同跳闸命令。
- 与过流保护的交互：只篡改一套互感器会同时形成差流，差动保护先于过流保护出口并断开断路器；两者同时动作属预期行为。

派生场景（`em-attack`/`sensor-attack`/`time-attack`/`network-attack`/`attack-demo`/`goose-*`）仍为单套授时与合并单元，需要时按同一方案同步。

### 冷却支路移到过程层最右列

`ctl_cool`（冷却系统控制接口）与 `cool`（冷却风机）由过程层第 3 列 `x=330` 移到过程层最右列 `x=870`，仍是同列上下相邻（接口在上、风机在下），使冷却支路成为过程层最外侧一目了然的一组。

为腾出最右列，其余过程层与站控层设备整列左移一格（保持原有相对次序）：`time_svc_2`/`mu_2`/`ct_current_2` 由 `x=870` 移到 `x=735`（仍竖直成列，专用对时线与采集接线仍为直连），`time_svc`/`mu`/`ct_current` 由 `x=600` 移到 `x=465`，`comp`/`vt_voltage` 由 `x=735` 移到 `x=600`，`oil_temp` 由 `x=465` 移到 `x=330`；授时卫星 `gnss_sat` 随之移到新的中位 `x=600`。分层带、两台交换机、两个 IDS 与安全监测平台均未移动，画布尺寸不变。

变压器到油温计的热耦合走线（`deployment.direct_links["L-tap-oil"].points`）随油温测点收窄到 `x=375`（新油温测点正下方），其余链路端点由设备坐标推导，无需手工调整。

### 交换机接入端口与走线

新增过程层与间隔层设备后，过程网交换机有 8 台设备接入。原先“端口按固定间距排在左侧边”的算法会让末尾端口落到轮廓之外，多台设备同时超出时还会共用同一条边线而相互重叠。现改为：

- 接入线仍全部落在交换机**左侧边**；按接入点相对交换机中心分成上方、下方两组。
- 每组最多分开显示 **3 条**线，两组合计的线条数不超过左侧边容量（由交换机高度推导：`floor((height - 2×12) / 12) + 1`）。
- 组内按离交换机的远近分配：**离交换机越远的设备优先独占一条线**；线条不够时，靠得近的溢出接入并入该组最外侧那条线（上方组为最上、下方组为最下），与相邻设备共用同一条线。
- 独占线条的设备中，越靠近交换机的线越靠外侧：上方设备越靠近越靠上，下方设备越靠近越靠下。
- 由于线条顺序与设备 x 单调一致，接入走线不会穿过其它设备的竖线（已加测试断言）。

以基准场景过程网为例（自上而下）：`diff_prot`、`mc`、`prot`（上方设备）；`ctl_brk`、`ctl_tap` 各占一条，`mu`+`mu_2`+`ctl_cool` 共用最下面那条（三台都是离交换机最近的接入，冷却接口移到最右列后进入这一组）。过程网 `connections` 的端口号按此顺序重排为 P1–P8，与画面自上而下一致；站控网 `station`/`prot`/`mc`/`diff_prot` 对应 P1–P4 不变。端口位置由设备坐标计算、端口号只是标识，改动仅在前端版式模块 `network-topology.js` 与基准场景的端口次序，后台路由与消息投递不受影响。

## 验证方式

```powershell
node --check sim2030/presentation/static/app.js
node --check sim2030/presentation/static/measurement-sources.js
node --test tests/test_network_topology.cjs
node --test tests/test_measurement_sources.cjs
python -m unittest discover -s tests -t .
```
